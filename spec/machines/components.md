# 机器组件生命周期工程约定（P4-T1）

## §1 范围

方块实体在重建端显式登记组件，并由宿主驱动其生命周期。以下顺序属于工程契约。服务器与世界会话遵循[平台生命周期](../platform/lifecycle.md)。

每个方块实体拥有独立的有序组件组和保存状态。只有所属逻辑服务端的宿主线程可以驱动组件。

## §2 加载、逐刻与卸载

- 服务端按登记顺序加载组件。加载成功后，每个服务端机器刻按相同顺序各执行一次。卸载期间暂停，重新加载后的首刻只推进一次。
- 正常卸载或移除时，对已加载的组件按加载的相反顺序各卸载一次。重复加载通知不得重复加载，重复卸载或移除通知不得重复卸载。再次加载开始新的加载周期。
- 成功工作的一刻如果改变了持久状态，则通知宿主保存。空闲且状态相同时跳过保存通知。
- 加载失败时，按相反顺序卸载已成功加载的组件。失败组件释放自己已取得的资源。机器回到未加载状态，调用方收到异常。
- 一个卸载回调失败时，仍须尝试卸载其余组件。全部尝试结束后向调用方报告失败。重复通知只释放一次。
- 加载或逐刻回调中同步拆机时，当前回调返回后停止派发，并按相反顺序各卸载一次已加载组件。加载中发生拆机后，机器回到未加载状态。

## §3 存档边界

原位存档保存剩余燃料刻和储能。基础火力机的容量和燃烧计量见[能量设备 §2、§5](../energy/devices.md)。

## §4 可复核条件

使用两台独立机器，各装两个能记录回调的组件。验证加载、工作、卸载、重复通知和再次加载，核对每台机器的回调顺序和次数。分别记录工作刻与空闲刻的保存通知，再验证加载失败、卸载异常和回调中同步移除。
