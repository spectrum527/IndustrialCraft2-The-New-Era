# 平台服务契约（P2-T2）

## §1 依赖方向与分批

Core 拥有 `common` 的接口。各版本的 Platform 适配器实现接口，在各自入口组装 `Platform`，再通过构造函数注入给消费方。QA 用纯 Java 测试共同逻辑，用对应版本的开发环境验证适配。
`Platform` 提供下列六个非空服务；同一实例内每项服务保持同一身份。专用服务器也提供客户端门面。实例状态随所属运行环境持有，不通过静态单例或全局可变注册表共享。
接口只用 Java 21 和项目自有的中立类型；加载器、游戏版本专属类型及其事件、缓冲区和句柄留在适配层。除另有约定，调用方不传空引用；参数错误和阶段错误必须显式失败。

| 执行批次 | 依据章节 | 共同接口源码 |

| T2a | §2–3、§8 | 注册、事件（2 文件） |

| T2c | §1、§6–8 | 客户端、配置、平台组装入口（3 文件；依赖 a/b） |

各门面可内嵌契约所需的小类型。a/b 可分别落地，无须引用尚未定义的门面或提交占位 `Platform`。本页定义接口边界；具体适配、生命周期、配置键、网络协议和客户端功能由对应任务另行规定。

## §2 注册（RegistryFacade）

- 开放登记阶段接受 `Kind<T>`、`Id` 和 `Supplier<? extends T>`，返回 `Handle<T>`。登记时仅保存工厂，句柄在绑定成功后返回同一结果。
- `Kind<T>` 由中立的注册种类名称和 `Class<T>` 类型令牌组成。名称须非空，名称与令牌均须为非 `null`。
- `Id` 接受符合 `ia2:[a-z0-9/._-]+` 的完整 ID。路径须非空，字符限于 ASCII 小写字母、数字和 `/._-`。构造参数为 `null` 或不符合规则时显式失败。
- **边界**：同一实例内以（种类，ID）判重。同 ID 可用于不同种类。版本适配器只在宿主注册阶段调用工厂，成功绑定须求值一次；读取未就绪句柄不能触发求值。
- **失败**：无效 ID、不可用种类、重复登记或封闭后提交均拒绝；重复登记保留首次登记。过早读取显式失败；工厂返回空值或抛异常使该条绑定失败，不重试，句柄保持失败，不发布半成品。

## §3 事件（EventFacade）

- 订阅接收 `Class<E>` 类型令牌和中立回调，发布接收类型令牌与该类型的事件值。发布按令牌精确匹配订阅，并按订阅顺序同步通知。无订阅者时正常完成。
- 订阅返回实现 `AutoCloseable` 的 `Subscription`。关闭方法无受检异常。
- **边界**：同一事件流的订阅、关闭和派发由同一宿主线程执行。每次派发只考虑开始时已有的订阅；关闭立即生效，尚未调用的已关闭订阅跳过，重复关闭无副作用。
- **重入与失败**：回调中的再次发布是独立派发，使用当时的订阅状态；新订阅不加入外层正在进行的派发。回调异常终止当次派发并传给发布方；订阅关系不因异常自动重置。

## §4 网络（NetworkFacade）

- `MessageType<M>` 包含本实例唯一的 `String id`、`Codec<M>`、`int maxFrameBytes` 和固定的逻辑 `Direction`（客户端→服务端或服务端→客户端）。ID 须完整匹配 `ia2:[a-z0-9/._-]+`，引用组件均为非 `null`。帧上限按编码所得的字节数计，允许为 0，负数显式失败。
- `register` 声明消息类型，`bindReceiver` 为已登记的类型在其接收侧单独绑定处理器。发送使用已登记的类型及该类型的消息。客户端发往当前连接的服务端，服务端须指定本实例的中立接收目标 `Peer`。发送成功仅表示本地受理。
- `Codec<M>` 将消息编码为 `byte[]`，从适配器提供的有界 `ByteBuffer` 解码。解码开始时位置为 0，容量与上限均为已校验的当前帧字节数。解码应推进位置，返回时位置须等于原帧长。
- **边界**：接收侧以实际连接判断方向与来源，先检查 ID、方向和帧长，再用登记的解码器校验字段及帧是否完整且无多余字节。校验不可信长度后才按其分配内存。合法消息在对应逻辑侧的宿主线程交给处理器；编解码本身不改变游戏状态。
- **失败**：重复声明须拒绝；使用未登记声明、方向错误、编码无效、帧超长或连接不可用的本地发送也须拒绝。未知 ID、错误方向、超长、截断或解码不合法的入站数据不得进入处理器。适配器按后续协议规定丢弃报文或断开违规连接。禁止反射序列化及从报文加载类型；具体消息、字段上限、握手、权限检查由后续协议规格定义。

## §5 能力（CapabilityFacade）

- `find` 接受 `Key<T>`、本实例的中立 `Target` 和 `Optional<Face>`。`Face` 表示上、下、北、南、西、东六面，空 `Optional` 表示无指定查询面。
- `Key<T>` 由非空名称和 `Class<T>` 类型令牌组成，两者均为非 `null`。能力存在时返回包含该声明类型值的 `Optional`。未登记能力、无提供者、目标已卸载或该方位无能力时返回空 `Optional`。
- **边界**：适配器绑定并查询能力，不为查找隐式加载区块或创建目标；查询结果不保证跨目标卸载或世界切换有效。
- **失败**：拒绝跨实例句柄或已声明键的类型不匹配；适配返回错类型是实现错误，不伪装成无能力。

## §6 客户端（ClientFacade）

- **输入与输出**：接受中立的延迟初始化动作。物理客户端在适配器的客户端初始化窗口受理并执行该动作一次，返回已受理；专服返回未适用，不入队、不求值。
- **边界**：共同入口、参数和返回值不得链接客户端类；仅物理客户端适配器进入其实现后才能构造引用客户端类的动作。是否处于专服不由世界的逻辑侧推断。
- **失败**：物理客户端窗口外调用显式失败；动作抛异常时报告客户端初始化失败，不在服务端补跑。

## §7 配置（ConfigFacade）

- **输入与输出**：读取当前不可变快照；尚未装载时返回空 `Optional`。在快照上以已声明的类型化键读取对应类型的值，无字符串到值的隐式转换。
- **边界**：适配器验证整份配置后一次发布新快照；同一快照的多次读取结果不变，旧快照继续可读。消费者不修改快照（含集合值）或注册键。
- **失败**：未知键或类型不匹配显式失败；缺少必需值或校验失败不发布该快照，保留最近一次成功快照（若有）。键、默认值、作用域和重载流程由配置规格定义（A10）。

## §8 接口验收

只验收当批实际交付的代码。只有接口声明时核对类型和依赖，行为仍记为未实现；下列行为用例须运行真实被测代码，替身只提供输入或依赖。版本适配交付后再验证其实际行为。

- **T2a**：验证同种类重复登记、跨种类同 ID、延迟工厂和失败句柄；验证回调中关闭尚未调用的订阅并新增订阅，观察外层与重入派发的不同顺序。
- **T2b**：验证两个合法方向各触发对应处理器；错误方向、未知 ID、超长和解码失败均未触发处理器；验证无能力与错类型可区分。未规定的实际协议不属于本批。
- **T2c**：验证两个注入实例互不污染；专服路径不执行动作且不需要客户端实现类；快照更新与校验失败均不改变已取得的快照。
