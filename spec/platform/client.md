# 客户端入口与资源重载（P2-T7）

## §1 物理侧与登记时机

物理客户端在各项宿主登记窗口挂接屏幕、按键和重载监听器各一次。客户端动作只能在物理侧选择完成后构造。专服走共同入口启动、载入世界并运行，不解析屏幕、按键、渲染或资源加载器的客户端类型。集成服务器的逻辑服务端继续按服务端规则处理世界。[客户端门面 §6](services.md)

1.21.1 使用 `RegisterKeyMappingsEvent`、`RegisterMenuScreensEvent` 和 `RegisterClientReloadListenersEvent`。26.1.2 与 26.2 的适配器分别使用各目标公开 API 的登记窗口；具体 API 由目标版本编译验证。启动、换世界、换服和资源重载都不会增加第二套绑定。

## §2 可操作的入口

在控制设置中提供可重绑动作 `key.ic2.open_status`，初始未绑定。玩家进世界、绑定空闲按键并按下一次，应打开一个本地只读 IC2 状态屏。屏幕有可读标题，并显示本次连接可核对的状态或当前客户端资源信息。Esc 关闭后返回游戏，玩家可再次打开。标题和按键名称使用可替换的语言资源。[NeoForge 按键映射](https://docs.neoforged.net/docs/1.21.1/misc/keymappings/)

处理按下事件时读取实际绑定和当前上下文。玩家在聊天输入框、主菜单或其他打开的屏幕按下该键，不应切换屏幕或把动作留到关屏后再执行。按住一次不能反复堆叠屏幕。状态屏只在客户端打开，无须虚构服务端容器。有真实容器的测试屏则须登记客户端工厂，由服务端打开对应菜单并带上本次菜单实例。测试菜单、测试物品与测试资源均从开发夹具提供。

## §3 资源重载与换服

客户端加载资源及玩家触发 F3+T 时，使用当前启用的资源包准备数据，成功后让后续显示读取新资源。准备或解析失败时，保留上一次成功可用的数据并报告失败。再次成功重载能够恢复。记录一次实际应用完成及当前可见内容。单有键盘事件或重载开始日志不足以确认。

退出服务器或切换到另一服务器时丢弃上一连接的会话信息。客户端资源包依宿主当前选择生效。资源重载不会重新登记消息、按键、菜单或重复安装监听器。客户端资源无法改动服务器配置或世界状态。

## §4 双端验收

1. 主基线分别启动干净的 1.21.1 客户端和专服，记录主菜单、专服世界启动且可连接。控制设置中该项恰好一条，未绑定时不响应。重新绑定后打开、Esc 关闭，聊天时按键不会打开，回到游戏后也不会补开。用开发菜单验证服务端打开、客户端正确建屏及关闭。
2. 准备包含明显不同状态屏标题或信息文本的外部资源包。记录更换前可见文字，启用资源包并完成重载，再次打开屏幕读到新文字。随后关闭资源包再装回原文。对监听器自身的失败候选，验证上一个成功数据仍然可读，随后成功应用一次。保存客户端截图或可访问文本及对应日志。
3. 与专服 A 实际收发 echo，离开再连同版本专服或新集成服务器 B，验证新屏不会显示 A 的回执。专服日志、独立的仅服务器加载测试及生产 JAR 检查共同验证物理侧隔离。三个目标分别编译。开发夹具、测试资源和测试 mod 在三个生产 JAR 中均无条目；26.1.2 与 26.2 从 P6 起各自运行上述验收。[网络验收](network.md) · [生产包隔离](verification.md)
