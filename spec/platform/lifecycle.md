# 服务器与世界生命周期（P2-T4）

## §1 实例、线程与事件

每个模组运行实例有一次共同初始化。每次打开存档建立一个新的服务器会话。专用服务器和集成服务器使用同一组逻辑服务端事件。物理客户端的世界不进入这组事件。版本入口显式转发事件，订阅者通过类型化事件流接收通知。初始化可在加载线程完成。一个会话的世界、刻和停止操作由该服务器的宿主线程串行处理。[事件契约 §3](services.md)

| 输入 | 转发时机与可观察输出 |
| --- | --- |
| 初始化 | 组装本实例服务后进入就绪状态，记录一次初始化。 |
| 服务器开始 | 在服务器首次加载世界前建立会话，记录一次开始。两版可接入 `ServerAboutToStartEvent`。 |
| 世界加载 | 每个实际加载的 `ServerLevel` 在 `LevelEvent.Load` 加入本会话。对外提供维度注册 ID，订阅者此时可查到该世界。 |
| 服务器刻 | 每次 `ServerTickEvent.Post` 产生一次服务器刻通知，无论有多少维度。可用会话内从 1 起的递增序号对账。 |
| 世界卸载 | `LevelEvent.Unload` 移除对应服务端世界并通知其维度。卸载后不得继续把旧世界交给消费者。 |
| 服务器结束 | `ServerStoppedEvent` 的处理完成后，释放该会话仍持有的世界及监听资源，记录一次结束。会话已结束时读取活动世界应为空。 |

## §2 顺序与再次开档

先初始化，后开始会话。每一维度先加载，后卸载。同一维度在卸载后可重新加载。不同维度的加载和卸载采用宿主实际顺序。服务器刻仅在会话存续时接收。停止清理遇到尚未收到卸载的世界时也须释放，每个世界只清理一次。服务器开始和结束各保留一条可对齐的运行日志。逐刻验证可通过显式订阅记录，避免正式服每刻刷屏。

同一客户端退回主菜单、另开一档时，共同初始化仍为一次，新会话从空世界集合和初始刻序号开始。以前的世界、连接和会话专属订阅不可在新会话被观察到。普通区块卸载不等同于整维度卸载，消费者须另接区块事件处理其本地资源。

## §3 拒绝条件

重复初始化、未初始化就启动、已有会话又启动、无会话时接收刻或停止、同维度重复加载、卸载未知维度、错误线程调用会话操作均显式失败。拒绝后保持原状态，订阅者收不到该次通知。空世界 ID 属参数错误。版本适配器先过滤逻辑客户端事件，避免集成服把同名的客户端世界误当重复加载。

## §4 可复核的运行

组件测试使用两个不同维度，依次输入初始化、启动、加载 A、加载 B、两个服务器刻、卸载 A、停止。验两次刻、A 仅清理一次、B 在停止完成时已释放。再启动，重用维度 A，首刻序号为 1。另对 §3 的错误输入分别验证原状态及通知次数。

1.21.1 专服在同一份日志中留下开始、主世界加载、至少一次实际服务器刻、主世界卸载和结束。停止后进程正常退出。集成服返回主菜单再打开一档，核对新会话与维度。两版构建均须通过。G2 还要求双端加载、真实方块放置与破坏及存盘读回、双向网络 echo、配置修改生效，以及 common 无 NeoForge 依赖。[适配验收](adapters.md) · [构建取证](verification.md)
