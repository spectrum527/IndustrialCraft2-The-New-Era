# 机器规格模板

> 一台机器一页；仅描述行为。以下字段均必填；无此能力写“不适用”，未核验写“待确认 + 责任任务”，不得猜值。

## 1. 身份与依据（字段说明）
| 字段 | 说明 / 必填内容 |
|---|---|
| id / name / purpose | 本项目 ID 使用 `ia2:`；名称、用途与工业链位置 |
| evidence / status | 区分静态核验、参考实例实测、设计示例、待确认；记录核验版本与未实测范围 |
| config | 仅列活配置键、默认值、单位、禁用/极值行为；没有专用键须明确 |

## 2. 参数、方块与槽位
| 字段 | 说明 / 必填内容 |
|---|---|
| block | 硬度、抗性、工具条件、放置/旋转、普通/扳手掉落、物品堆叠数 |
| tier / energy_capacity | tier（无量纲）与单包 EU 分列；区分容量基数、加载后有效 EU；说明输入面与限流 |
| energy_consumption / operation_length | EU/t、tick/次；空闲与停机耗能、计费时点、取整方法 |
| recipe_type / slots | 配方类型；逐槽数量、容量、合法内容、玩家/自动化权限、世界面/相对面 |

## 3. 行为与升级
| 字段 | 说明 / 必填内容 |
|---|---|
| states | 空闲、工作、断电、堵塞、完成的转移；输入扣除、结果提交、缓存失效、存档恢复时点 |
| upgrades | 槽数/堆叠上限、接受/拒绝类型、公式与取整、重算时机、进度及已有储能的处理 |
| automation | 优先面是否排他；有效输入能否抽出、失效输入处理、升级传输数量/方向/时序 |

## 4. 输入
列出玩家交互、物品/流体/能量/红石输入及权限；无红石控制也须写明。

## 5. 输出
列出产物、方块 active、GUI 同步量、比较器公式及音效生命周期；不能以资源名代替触发条件。

## 6. 边界与失败模式
分别写断料、断电、输出不足、换配方、卸载、非法输入、过压；修复项写“重建行为 = 修复后（B#编号）”。另列“原版 bug（回归用例）”及触发输入。

## 7. 配方与 parity 场景
逐例列配方 ID、精确输入/输出/数量/概率、容器余物、时间和能量由谁决定。场景须有初态、操作 tick、期望值、容差及采集状态；未交付的 parity 文件不可冒充已存在。

## 8. 示例与依赖
完整静态核验示例：[`打粉机`](../machines/macerator.md) §1–§8；参考实例尚未运行。
核验提示：该示例容量基数为 600 EU，加载后默认有效容量为 1200 EU；默认 2 EU/t、300 tick/次，不是通用机器默认值。tier 1 对应 32 EU/包，不等于总输入上限。
列出已交付依赖、尚待交付章节及阻塞的行为；实现者不得自行补全待确认项。
