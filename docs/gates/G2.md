## 复跑

从仓库根目录执行，Gradle 使用已锁定的工具链。实机命令需要可用的图形会话，每次指定新的验收目录。

```sh
./gradlew --no-build-cache clean build :test:runPlatformHostTest :test:runPlatformWorldTest :test:runGameTest :neoforge:1.21.1:preparePlatformPlay
python3 src/test/platform_play_check.py --prepared --directory build/g2-client
python3 src/test/client_acceptance.py --prepared --mode bad --directory build/g2-protocol-mismatch
```

双进程专服的状态、退出码和前后 JAR 指纹在 1.21.1 模块的 `build/run/platformWorld/`。物理客户端检查写入指定目录的 `play-checks.json`，负例写入 `mismatch-result.json`。区分负例版本时以启动清单和类指纹为准，报告也保留了 NeoForge 的原始拒绝文字。

## 接入下一台机器

- 在加载器的注册阶段通过本实例的 `Platform.registry()` 登记方块和物品。保存类型化句柄，待原生注册完成后求值。1.21.1 的测试柱演示了独立开发模组通过容器扩展取得同一实例。[宿主契约](../../spec/platform/adapters.md) · [运行示例](../../src/test/src/gameTest/java/com/industrialage/ia2/gametest/PlatformWorldFixture.java)
- 将实际需要的服务注入机器逻辑。六面 IO 使用 `CapabilityFacade` 并在当前位置查询，世界和区块卸载后释放旧目标。服务器刻只按服务端发生一次。[生命周期](../../spec/platform/lifecycle.md)
- 服务端从当前配置视图取不可变快照。同一操作使用同一快照，下一次操作再读取最新值。每个存档使用 `serverconfig/ic2-server.toml`，管理员通过 `/ic2 config reload` 发布有效修改。[配置装载和重载](../../spec/config/runtime.md)
