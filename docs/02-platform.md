## 选择理由

主基线固定在 1.21.1，使 MVP 的构建、客户端、专用服务器和 G5 验收有统一目标。26.1.2 与 26.2 同步编译可尽早暴露版本耦合，两个目标各自的运行门禁从 P6 起加入。1.19.2 独立作为行为参照，避免把旧环境的二进制兼容要求带入重建架构。

ModDevGradle 是已批准的构建方案；P0-T4 当时对 1.21.1 / 26.1 组合执行本地双版本构建，并记录 Wrapper 与依赖校验和。选型记录、编译证据、运行证据和 CI 结果分别保留，不能把历史结果算作新组合的验证。

## 三目标子模块结构

以下为 `26.2` 集成分支的目标职责边界；`26.1.2` 分支先完成其中前两个目标：

```text
src/
  common/             核心行为、内容定义与平台能力接口
  neoforge/
    shared/           跨目标共用的平台 Java
    1.21.1/           主基线注册、事件、网络、能力与客户端适配
    26.1.2/           同步目标的构建与专属适配
    26.2/             同步目标的构建与专属适配
    26.x/src/main/java/ 两个 26.x 目标共用的 Java 适配
  datagen/            数据生成入口，按目标版本连接适配层
  test/               核心单测及各目标平台的运行测试
```

依赖由版本适配层指向 common，common 不依赖任一适配模块，也不得引用平台或版本专属 API。平台能力通过小接口注入；版本差异收敛在对应适配层。内容 PR 须编译所在分支的全部目标；集成分支须编译三个目标。主基线的运行结果不能替代同步目标的编译或运行结果。

原版素材仍在独立私有素材仓库，通过可选属性 `ic2.legacyAssetsDir`（保留旧属性别名） 引入；属性缺省时跳过该资源目录。新作资源放在 `assets/` 并在同路径时优先。外部 PNG 及其动画元数据只供参考；构建过滤这些图像，包括机器 GUI，详情见 A22。素材文件不得进入主仓库历史；P0-T4 必须验证有、无外部素材目录两种构建情形（A22）。

## 风险与验证责任

| 风险 | 处理及验收责任 |
|---|---|
| 平台组合与升级兼容性 | 保持固定版本和校验值；升级后重跑三个目标的编译及对应运行门禁 |
| 版本专属类型渗入核心层 | 编译三个目标并检查 common 的导入；发现耦合时收敛到能力接口 |
| 各目标的客户端、网络或存档行为分歧 | 分开记录各目标结果；从 P6 起分别加入 26.1.2 与 26.2 运行验收 |
| 仅编译通过，实际无法加载 | P0/P2 分别保留构建证据与客户端、专用服务器加载证据 |
| 外部素材目录缺失或资源覆盖顺序错误 | 分别构建并检查生成包；确认新作同路径优先且历史中无原版素材 |

## 回退方案

单次构建或适配回归可回到最后通过验证的依赖组合或实现提交；保留失败日志，再由对应角色修复。不能通过静默删除任一目标的编译检查来恢复绿色状态。

如负责人后续批准改用 Forge 1.19.2 作为发布目标，应先通过决策 PR 修改 A5，再建立对应的平台适配模块；核心行为与接口边界保持不变，只调整平台实现、构建入口及必要的数据兼容层。该方案是条件性的风险预案，当前仍执行 NeoForge 三目标，不新增 1.19.2 发布承诺。
