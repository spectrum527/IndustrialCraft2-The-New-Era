# 打粉机参考采样

本次实测依据 `spec/machines/macerator.md` §2–§7 和 P0-T5 约定。参考实例使用 JDK 17、Minecraft 1.19.2、Forge 43.1.24、ForgeGradle 5.1.77 和 Gradle 7.5，离线开发用户名为 `ParityQA`。

2026-11-11 实际进入了种子 7 的创造模式超平坦世界。玩家获得打粉机并将其放在 `[0,64,0]`，右键打开了机器界面。保存并退出客户端后，重新启动并进入同一存档，原位机器的界面仍可打开。截图、完整启动和退出日志及逐 tick 原始采样留在私有运行目录。

| 场景 | 初态 | 实测 |
| --- | --- | --- |
| M01 | 煤 1 个、600 EU、进度 0 | 采集 0–300 tick 共 301 个状态。每 tick 储能下降 2 EU。第 299 tick 余 2 EU、煤 1 个、输出为空。第 300 tick 储能归零，输入为空，输出煤粉 1 个，进度归零。 |
| M08 | 煤 2 个、1200 EU、进度 0 | 采集 0–600 tick 共 601 个状态。第 299 至 300 tick 储能由 602 降至 598 EU，输出煤粉 1 个。第 599 tick 储能归零，进度为 299，`active=true`。第 600 tick 保留煤和煤粉各 1 个、进度 299，`active=false`。 |

`macerator-M01.json` 保留依据规格编制的配对计划，`results=[]` 表示双边比较未执行，不能据此宣称验收通过。M01 和 M08 的 `*-observations.json` 使用单边记录格式 `ia2.reference-observation.v1`，`source_role=reference` 表明数据来自参考端。M08 仅记录观测，连续计费行为交由负责人评审。

机器下方平台位于 y=63，x=-4..4、z=-4..5。两次运行的第 0 tick 均确认输出、升级槽和放电槽为空，周围布置无外部供能。夹具重置机器时掉落的旧物品留在平台上，采样读取机器内部输入和输出槽。

1. 启动私有 ForgeGradle 参考实例并创建上述世界。在游戏内执行自编夹具 `/qa layout` 领取机器，将机器放在平台中心并打开界面。
2. 保存退出至标题页，关闭客户端，再启动并进入同一世界，重新打开机器界面。
3. 在机器界面放入一块煤，用 `/qa dump` 观察公开的机器状态和输入槽序列化格式。本次记录的无侧向物品能力查询返回空，采样取公开序列化数据中的槽位记录。
4. 在私有控制文件填写本次初态。执行 `/qa run` 后，夹具在下一个服务端 tick 开始时重置同位置机器并载入该状态。夹具记录第 0 tick，随后按世界 game time 增量记录每个服务端 tick 结束的状态。
5. M01 记录 300 tick，M08 记录 600 tick。核对 tick 连续性和第 0 tick 后，从原始采样提取 `sample_at` 指定的关键行。

记录中的 `planned_setup` 与 `sample_at` 描述试验条件。`results` 保存实测储能（EU）、进度（tick）、输入和输出数量及方块 `active` 状态。物品 ID 使用项目行为名称。数量为 0 时，物品 ID 为 `null`，表示该槽为空。不可访问的字段用 `null` 并注明原因。本次两场景的所列采样字段均有观测值。
