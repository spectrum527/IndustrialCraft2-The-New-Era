# 打粉机参考采样

依据 `spec/machines/macerator.md` §2–§7、P0-T5 任务约定及项目 QA 容差条款。本目录只放行为计划和允许公开的观测；运行实例、输入包、运行映射、原始 NBT、截图与完整日志均留在私有运行目录。

当前状态（2026-11-11）：私有夹具编译与客户端加载日志已验证；Mac 锁定，世界、放置、GUI、退出重入及 M01/M08 采样均 blocked。客户端进程已结束，等待用户手动解锁后恢复。P0-T5 尚未完成。`macerator-M01.json` 是配对比较计划，`results:[]` 表示双边比较未执行；不能视为验收通过。参考端观测将独立记录，不使用参考数据代填 candidate。

M08 不制作带固定容差的配对计划，以免把尚待负责人决定的连续计费行为误当验收期望。单边记录模板为 `macerator-M08-observations.json`，当前 `results:[]`。其 `record_format=ia2.reference-observation.v1` 独立于上级配对 schema；采样后可导出 CSV，配对计划继续遵循上级 schema。

布置：机器位于 `[0,64,0]`；平台位于 y=63、x=-4..4、z=-4..5；附近不放供能器或其他库存。世界种子计划为 7，离线开发用户名为 `ParityQA`。CSV 中的逻辑输入/输出槽与运行实例的实际槽位绑定由私有适配记录承担。

执行步骤：

1. 用固定 JDK 17、Minecraft 1.19.2、Forge 43.1.24 的私有 ForgeGradle 实例启动客户端，创建种子 7 的创造模式单人世界并启用命令。
2. 执行自编私有夹具 `/qa layout`，获得实际机器物品；玩家在指定位置放置机器，右键打开 GUI，用游戏截图键保存证据。
3. 执行 `/qa dump`，从公开序列化数据及物品能力确认可观测字段与实际槽位；不查看实现资料。
4. 在私有控制文件中设置 M01 初态和 300 tick。`/qa run` 将在下一个服务端 tick 开始时重置同位置机器，并用公开 API 设置初态、插入原料。
5. 夹具在 tick 开始前记录初态，以世界 game time 增量计数，在 tick 结束后逐 tick 保存 NBT、方块状态和库存；暂停不会被当作机器运行时间。
6. 同样执行 M08 的 600 tick，仅记录事实。缺失字段留空并说明限制，不推导不存在的观测值。
7. 保存退出、关闭客户端，再次启动并进入同一世界；重新打开机器 GUI 并保存日志和截图，验证可继续操作。

原始逐 tick 记录是单边参考数据。对外 CSV 只保留时间、电量、进度、输入/输出数量和可观测 active，并将行为 ID 转为 `ia2:`；原始运行标识的映射不进入本仓库。静态期望、参考观测和双边比较结论必须分别标明。

单边记录的 `planned_setup`、`ticks` 与 `sample_at` 是待执行计划，不是观测值。执行状态另记于 `execution`；没有实测时 `results` 必须为空。采样后每行记录 `elapsed_tick`（非负整数）、`stored_eu`（数值）、`progress_tick`（数值）、`input_item/output_item`（中性行为 ID）、`input_count/output_count`（非负整数）、`active`（布尔）。不可访问字段用 null 并说明原因，不能以零代填。记录中没有 candidate、通过阈值或修复结论。

本次已验证：固定工具链下 `compileJava` 成功；启动日志显示离线用户名、固定平台和模组加载；输入包哈希未改变。未验证：世界、方块交互、GUI、重入、能耗、时长、产出和连续计费。下一步依赖用户手动解锁，再从同一私有实例恢复；不能把启动日志或空结果当成 parity 通过。
