# 注册表和生存路线审计

`acquisition.tsv` 每行对应修复版一个普通方块或物品登记。`reference_recipe` 来自修复版服务端原生 RecipeManager 的固定产物，动态配方的产物可能因输入而变化。`reference_creative_tab` 记录物品登记的创意栏归属。候选端实际启动后从注册表枚举全部 ID，逐版对照。`summary.json` 记录候选包 SHA-256、缺失、额外内容、模型或方块状态文件和待验证的生存路径。

路线从装入包的数据包、原生设备配方目录与已知世界交互求可达闭包。`recipe` 表示普通制作或烧炼，`device` 表示工业设备产物，`exploration` 表示结构箱战利品，`worldgen` 表示自然世界生成，`world-use` 表示玩家操作或作物产物，`loot` 表示采集方块掉落，`placement` 表示放置已可取得的物品。多种路径列出实际类别，末列保留至多四条示例。基础原版资源及标签可获取是求闭包的前提。行为验收依据相邻 JSON 中逐项记录的实机试验。

`creative-only` 标记目前只通过创意模式取得的发电机和远程界面升级。重建版给两个高级搬运升级提供了补充生存配方。`internal` 标记原版无创意标签的调试物品。`unverified` 是仍需验证的生存路径，保留对照版原生配方字段供进一步排查。审计针对固定种子、原版环境与 IC2 候选，镶嵌兼容模组提供的银矿等资源仍需单独查验。
